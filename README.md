# ⚡ PageSpeed Insights & Core Web Vitals Audit Toolkit

[![Node.js](https://img.shields.io/badge/Node.js-18%2B-brightgreen.svg)](https://nodejs.org)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Google Lighthouse](https://img.shields.io/badge/Lighthouse-13.5-orange.svg)](https://developers.google.com/speed/pagespeed/insights/)
[![Core Web Vitals](https://img.shields.io/badge/Core%20Web%20Vitals-100%25%20Green-success.svg)](https://web.dev/vitals/)

Универсальный автономный софт для комплексного аудита производительности и **Core Web Vitals** любых веб-сайтов и страниц. Поддерживает запуск на **любом ПК** (Windows, macOS, Linux) без сложной настройки.

Работает в двух взаимодополняющих режимах:
1. **Облачный Google PageSpeed Insights API (v5):** мощный аудит на серверах Google, 0% нагрузки на процессор, получение полевых пользовательских данных (CrUX).
2. **Локальный движок Lighthouse CLI:** аудит локальных сайтов (`localhost:3000`), dev-серверов и страниц за авторизацией без ограничений по квотам.

Включает глубокий сравнительный анализ **Cold (холодный запуск)** и **Hot (горячий запуск)**, автоматический краулер карты сайта (`sitemap.xml`), интерактивные HTML-отчеты с графиками, Markdown-сводки, экспертную систему рекомендаций с примерами кода и интерактивную презентацию на базе кейса Workdo SaaS (83 страницы, 100/100).

## ⚡ Экспресс-запуск за 10 секунд (Quick Start)

### 1. Как запустить на любом компьютере:
* **На Windows:** просто дважды кликните по файлу **`run.bat`**.
  > 💡 **Авто-настройка при первом запуске:** скрипт `run.bat` автоматически проверит систему, при необходимости сам доустановит Lighthouse в локальную папку проекта (`npm install --no-audit --no-fund`) и запустит аудит. Никаких ручных манипуляций не требуется!
* **На macOS / Linux:** выполните в терминале:
  ```bash
  chmod +x run.sh && ./run.sh
  ```
* Введите URL сайта (например, `https://vstu.by/ru` или `https://workdo.ru`) и нажмите клавишу **Enter**.
* По завершении замера интерактивный HTML-дашборд откроется в браузере автоматически!

---

### 2. Нужен ли API-ключ Google?
* **Для большинства задач и лабораторных — НЕТ, ключ не нужен!**
  Основной рекомендуемый режим по умолчанию — **`[1] Локальный Lighthouse`** (выбирается простым нажатием Enter):
  * Работает автономно прямо на вашем ПК через браузер (**Google Chrome** или встроенный **Microsoft Edge**).
  * **Не зависит от серверов Google**, не блокируется учебными/университетскими сетями и не имеет лимитов по квотам (ошибок 429).
  * Полностью бесплатен и не требует никакой регистрации.

* **Можно ли использовать свой Google API Key?**  
  **ДА, можно!** Ключ полезен, если вы хотите использовать **Облачный режим `[2]`** (Google PageSpeed Insights API v5):
  * Замер выполняется мощностями дата-центров Google (0% нагрузки на ваш процессор);
  * Предоставляются реальные полевые данные пользователей (**Chrome User Experience Report / CrUX**);
  * Выделяется бесплатная квота **25 000 запросов в день**.

---

### 3. Где бесплатно получить официальный Google API Key:
1. 🔗 **Официальная страница Google для получения ключа:**  
   👉 **[https://developers.google.com/speed/docs/insights/v5/get-started](https://developers.google.com/speed/docs/insights/v5/get-started?hl=ru)**  
   *(нажмите синюю кнопку **«Get a Key» / «Получить ключ»**, авторизуйтесь под любым Google-аккаунтом — привязка банковских карт **не требуется**)*.
2. 🔗 **Прямое управление ключами в Google Cloud Console:**  
   👉 **[https://console.cloud.google.com/apis/credentials](https://console.cloud.google.com/apis/credentials)**

#### Как подключить полученный ключ в софт:
* **Способ 1 (через `.env`):** скопируйте файл `.env.example` в `.env` и впишите ключ:
  ```env
  GOOGLE_PAGESPEED_API_KEY=AIzaSy...ваш_ключ...
  ```
  *(Файл `.env` уже добавлен в `.gitignore` и защищён от случайной публикации на GitHub)*.
* **Способ 2 (через `config.json`):** откройте `config.json` и укажите ключ в поле `"apiKey"`:
  ```json
  "apiKey": "AIzaSy...ваш_ключ..."
  ```
* **Способ 3 (через CLI):** передайте ключ аргументом при запуске:
  ```bash
  node bin/psi-audit.mjs --url https://vstu.by/ru --key AIzaSy...ваш_ключ... --open
  ```

### 🛠️ Частые вопросы и решение проблем (Troubleshooting)

#### 1. Пишет: `[ERROR] Node.js is not found on this computer!`
* **Причина:** На компьютере не установлена среда Node.js.
* **Решение:** Перейдите на официальный сайт **[nodejs.org](https://nodejs.org/)**, скачайте установщик с пометкой **LTS** (зеленая кнопка), установите его со стандартными параметрами (галочка *Add to PATH*) и снова запустите `run.bat`.

#### 2. Ошибка: `Connect Timeout Error` или `fetch failed` при выборе облачного режима `[2]`
* **Причина:** Сеть университета, корпоративный Wi-Fi или провайдер блокирует прямые запросы к облачным IP-адресам Google Cloud.
* **Решение:** Всегда выбирайте режим **`[1] Локальный Lighthouse`** (он установлен по умолчанию при нажатии Enter). В этом режиме замер выполняется прямо на вашем ПК через установленный браузер, не требуя связи с серверами Google.

#### 3. На компьютере не установлен Google Chrome
* **Решение:** Ничего скачивать не нужно! Утилита автоматически обнаружит встроенный браузер **Microsoft Edge** (установлен на 100% ПК с Windows 10/11) и проведет замер через него.

#### 4. Как сдать лабораторную работу преподавателю?
* В репозитории уже подготовлен полный академический отчет по ГОСТ: откройте файл **[`LAB_REPORT_PERFORMANCE_AUDIT.docx`](LAB_REPORT_PERFORMANCE_AUDIT.docx)** в Microsoft Word.
* Для демонстрации откройте интерактивную презентацию **[`PRESENTATION.html`](PRESENTATION.html)** двойным кликом в браузере.

## ❄️ Cold vs 🔥 Hot: В чем разница?

Замерять скорость сайта только один раз — грубая ошибка:
* **Cold (Холодный запуск):** симулирует **первый визит** нового пользователя с пустым кэшем браузера. Все стили, шрифты WOFF2, JS-бандлы и изображения скачиваются по сети с нуля. В облачном API применяется cache-buster, в локальном — `Network.clearBrowserCache`.
* **Hot (Горячий запуск):** симулирует **повторный переход**. Статические файлы берутся из локального дискового/оперативного кэша браузера (304 Not Modified), TCP-соединение прогрето. Показывает чистую скорость серверных вычислений и гидратации React/Vue.

## ⚙️ Параметры командной строки

| Параметр | Описание | Значение по умолчанию |
|---|---|:---:|
| `--url <url>` | URL страницы (или несколько через запятую) | Интерактивный запрос |
| `--all`, `--crawl` | Протестировать ВСЕ страницы сайта через `sitemap.xml` | `false` |
| `--sitemap <url>` | Прямой адрес sitemap.xml для парсинга | `null` |
| `--limit <число>` | Лимит страниц при массовом парсинге sitemap | `30` |
| `--mode <режим>` | Режим аудита: `cold`, `hot` или `both` | `both` |
| `--device <девайс>`| Тип устройства: `desktop`, `mobile` или `both` | `desktop` |
| `--repeats <число>`| Количество повторных горячих замеров | `2` |
| `--key <apiKey>` | Ключ Google PageSpeed API | Из `.env` / `config.json` |
| `--config <файл>` | Путь к JSON-файлу с конфигурацией | `config.json` |
| `--out <папка>` | Папка для сохранения отчетов | `./reports` |
| `--local` | Использовать локальный Lighthouse вместо облака | Автоматически |
| `--open` | Автоматически открыть отчет в браузере | `false` |
